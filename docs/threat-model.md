# Threat Model

Этот lab рассматривает агента, который получает инструменты для анализа уязвимостей.

## Что защищаем

- целостность базы уязвимостей;
- секреты и конфигурацию;
- хост, на котором запускается агент;
- внешние API;
- действия, выполняемые от имени пользователя.

## Основные угрозы

### Prompt Injection
Недоверенный контент пытается изменить поведение модели: например, текст из документа просит проигнорировать инструкции и вызвать другой tool.

**Контроль:** не считать prompt границей безопасности; проверять tool-call отдельно.

### Excessive Agency
Агент получает больше возможностей, чем нужно для задачи.

**Контроль:** least privilege, минимальный набор опубликованных tools, read-only credentials.

### Tool Abuse
Модель выбирает легитимный инструмент, но использует его с опасными параметрами.

**Контроль:** schema validation, allowlist значений, лимиты и policy checks.

### Data Leakage
Агент получает доступ к данным, которые не нужны для текущей задачи, и может включить их в ответ или отправить наружу.

**Контроль:** data minimization, scopes, отдельные credentials, фильтрация чувствительных данных.

### Destructive Action
Tool меняет или удаляет данные.

**Контроль:** deny-by-default, HITL, отдельная write-role, audit trail, rollback там, где он возможен.

## Trust boundaries

```text
Untrusted input
      ↓
     LLM
      ↓
[ POLICY BOUNDARY ]
      ↓
 MCP / Tools
      ↓
Data / API / OS
```

LLM рассматривается как компонент, который может ошибиться или быть направлен недоверенным вводом. Поэтому авторизация должна происходить после решения модели и до реального side effect.
